# SonicClue specification package

Product: **SonicClue**, affordable sound and vibration cause investigation (Circuit Drift Labs).
Repository: `djshellshoxxx/SoniClue`. The product name is *SonicClue*; the repository keeps its existing name (ADR-0016).
Package version: spec 1.0.0 for software 0.1.0. Contract schema 1.0.0. Store layout v1. Ruleset 1.0.0. Analysis algorithm 1.0.0.

## How this package was produced

The baseline consists of the owner's *Master Project Specification Authoring Prompt* and the *Developer-Completeness Requirements* (both supplied 2026-10-12), plus the authoring prompt and handoff in `docs/prompts/`. The owner then explicitly authorised building the application ("create a fully featured app based on the specs created and the instructions"). Specification and implementation were therefore produced in the same session, in dependency order. Each spec states the contract the code implements and names the tests that verify it. See `24-specification-audit.md` for how that affects independence.

Status vocabulary (all registers): `CONFIRMED`, `SELECTED_DEFAULT`, `VALIDATION_REQUIRED`, `BLOCKED`. Verification status: `TESTED` (automated, passing), `IMPLEMENTED` (wired, no dedicated automated test), `UNEXECUTED` (written but not run, e.g. needs hardware), `NOT_STARTED`.
